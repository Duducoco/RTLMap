# Use typed true-volume subrectangles for coverage space

RTLMap represents each sample with five ten-dimensional axis-aligned subrectangles, one for each coverage type. A subrectangle's true geometric volume is supervised by that type's coverage density, and true-volume IoU is supervised by per-type coverage-set Jaccard similarity; defined types are aggregated with equal weight. The box dimension is deliberately separate from the 256-dimensional encoder state because a 256-dimensional true volume forces ordinary coverage densities to use nearly full per-axis widths and is numerically difficult to optimize. Training may use a smooth intersection surrogate to retain gradients, while validation and inference always report hard geometric volume and IoU. This representation is trained from scratch and does not support loading legacy hyperrectangle weights.
